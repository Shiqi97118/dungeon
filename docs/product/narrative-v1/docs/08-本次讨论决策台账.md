## D. 尚需接收方解决的工程问题（OPEN）

1. **账号体系**：现在是否已有稳定跨设备登录与服务端个人档案？如果没有，先 local profile 并提供显式绑定/导出，不能虚构账户同步能力。
2. **事件字段命名**：本包 JSON 里的 event types 是规范草案，Cursor/Codex 需与后续实际剧情引擎字段统一（见 `05`）。
3. **多人归属与后加入**：角色暂离、玩家退出、AI 代演、替补玩家的“31 次有效选择”和成就份额，需要结合当前房间模型明确。
4. **世界危机触发**：全局 0–12 的新推进节奏、沙盒玩家自愿结束的候选方向，需先在文档层得到无矛盾规则，之后试玩校准。
5. **成就账户与角色的传承**：同一账号多角色是否共享称号、传奇事迹是否允许导出和公开分享，涉及隐私与产品范围。
6. **动态成就提案审核**：允许 AI 自拟传奇事迹，但必须确定客观证据、去重、长度与内容安全审核，避免刷成就。
7. **图标美术验收**：本包首版 SVG/PNG 已可用，但是否作为最终艺术风格要结合当前 12 张样张和页面整体美术再评审。
8. **QTE 触发密度**：不要按每轮必须一次的方式硬塞；灰港垂直切片体验后再统一策划数量。
9. **音频与手机性能**：触摸、低耗电、慢设备、无声模式、屏幕阅读器；特别是有趣但不会影响原有角色掷骰公平的节奏交互。
