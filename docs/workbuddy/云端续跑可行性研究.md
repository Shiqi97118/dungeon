# Codex 与 WorkBuddy 云端续跑可行性研究

研究日期：2026-11-10。仅核查文档和现有接入，不购买、不创建云资源、不迁移正在执行的任务。

后续决定：用户已因费用取消云电脑方案，本文仅留作研究记录。当前执行方式以根目录 CONTINUE.md 为准，不按本文购买或部署云资源。

## 结论

可以实现本机关闭后继续执行，但执行器、调度器、任务记录、仓库和认证都必须在云端可用。现有 Windows 原生接口已验证文件交付和同会话返工；它还不是具备重启恢复能力的无人值守系统。下述云电脑路线属于基于现有能力的工程方案，尚未在云电脑实测。

近期优先考虑同一台持久化 Windows 云电脑运行 Codex、WorkBuddy 和桥接调度器；长期评估官方云端任务 API，以减少桌面会话依赖。不能仅把 WorkBuddy 搬到云端，却仍依赖本机这个聊天持续唤醒和审核。

## 路线一：同机云电脑

在同一台具有持久磁盘和图形桌面的 Windows 云电脑上运行：

- Codex 桌面端或 CLI：调度、读取成果、检查测试及返工。
- WorkBuddy 桌面端：设计、开发、美术角色执行。
- 桥接和持久队列：保存任务、会话、轮次、提交回执、模型、成果与审核结论。
- 游戏仓库和开发工具：串行修改业务代码，保留当前未提交改动。

Codex 官方提供非交互执行和指定会话恢复；WorkBuddy 官方 Windows 安装要求为 Windows 10+ x64。两者可以作为同机方案的组件，但官方文档并未证明本项目桥接器在某一云电脑供应商上的兼容性。Windows Server、ARM、特殊精简系统和不同桌面客户端版本均需另外验证。

关闭远程连接窗口与退出 Windows 用户会话不同。Microsoft 文档说明断开连接时应用可保持活动，前提是远端会话仍活动；云厂商的断连回收、休眠和会话超时策略需要核查。重启机器后的登录恢复、原生权限请求及 GUI 操作也不能仅靠系统服务保证。

## 路线二：官方云端能力

Codex Cloud 官方支持本机休眠时继续任务，并为每个任务提供独立工作空间。它不会自动带走本机文件、运行进程、登录状态和 VPN。

WorkBuddy 小程序官方支持云上沙箱，无需个人电脑；也有官方专家和专家团能力。但云上模式是否具备当前项目所需的 Git 操作、构建工具、专家配置、hy4free 和对应费用，仍需账号实测。

WorkBuddy 开放平台的文档索引列出云端任务接口：POST /openapi/v2/tasks，权限 user.task.invokable，并返回任务标识及 ACP 连接信息。第三方应用文档要求应用配置、审核及 OAuth 授权；个人账号能否申请这项权限尚未核实。不能把小程序云上模式可用等同于自动化 API 已授权，也不能假定云端专家与本地专家配置相同。

若拿到相应权限，可开发云端协调服务，让 Codex 向 WorkBuddy 云任务派工，通过受控成果交接和版本分支完成审核返工。两个官方沙箱没有天然共享磁盘，必须明确如何交付文件、同步版本与避免覆盖。

## 现有实现的迁移缺口

1. 当前桥接脚本包含本机绝对路径和本机专用会话；应改为机器配置，云端重新创建并核验真实会话，不能把本机 sessionId 直接用于另一台机器。
2. 当前 .local/ 被 Git 忽略，git clone 不会带走桥接源码和任务记录；仓库也有未提交的功能修改，迁移前必须备份或生成可核对补丁，不能只克隆远端默认分支。
3. 当前原生提交回执不等于完成；需要持久状态：待提交、已提交、执行中、待审核、已验收、需输入、失败和结果不确定。
4. 任务标识和轮次要稳定。断线后先查询原任务和真实文件；结果不确定时不自动重发。机器重启不能成为重复执行业务任务的理由。
5. 增加退出重开、网络恢复、日志轮转和异常通知。登录或原生权限失效时应暂停并通知，不绕过确认。
6. 调试端口继续仅绑定云电脑回环地址；管理链路另行鉴权，不把当前原生调试接口直接开放到公网。
7. 成果由 Codex 独立检查；不是让两个 agent 无限互相聊天。为每个任务设置执行期限、返工上限和费用限制，达到上限保留现场。

## 费用策略

- 分别核算云电脑、Codex 订阅或 API 用量、WorkBuddy 积分、存储和出网；WorkBuddy 积分不能抵扣云电脑或 Codex 成本。
- 免费 hy4 优先；必要时使用已核对的低积分模型，不能仅凭模型名推断便宜。云端和桌面端的模型供应与计费不假定一致。
- WorkBuddy 小程序官方模型页当前列出 DeepSeek-V4-Flash x0.06、DeepSeek-V4-Pro x0.16。它们是文档中的相对积分倍率，不是人民币单价，也不是已核对的本账号桌面报价；实际选择前须以对应端的界面和权限为准。
- 不先承诺固定月费。按时计费的机器若全天运行，一个30天月约720小时；还需计入系统盘、快照、网络及未停止的其他资源。先短时试验，再决定是否长期运行。

## 建议验证顺序

1. 确认现有云电脑或候选配置能合法、稳定访问两项服务，并有持久磁盘和持续桌面会话。暂不要求 GPU；实际资源规格用构建与并发测量决定。
2. 迁移仓库和接入程序、重新登录，保存任务交接单；迁移前先核对本机任务是否仍执行，避免两台机器重复派工。
3. 云端跑最小闭环：写文件 → 独立读取 → 同会话返工 → 测试 → 保存验收记录。
4. 本机断网并关闭远程连接至少2小时，确认云端任务能完成、继续派发下一项并留下记录，验证本机确实不再是依赖。
5. 分别测试应用退出重开、短暂断网、云电脑重启、认证失效、权限请求；验证不丢任务、不重复执行，需人工输入时可通知。
6. 做一夜稳定性和真实费用测量，再决定常驻。测试通过之前不宣称24小时无人值守可用。
