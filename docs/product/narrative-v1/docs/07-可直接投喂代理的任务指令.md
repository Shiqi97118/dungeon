## E. 推荐 Git 与协同工作流

1. Cursor 修改自己的 PR #5：剧情文档和文本。
2. Codex 自己的 `feat/event-achievement-core`：事件、规则和测试；基于在任务启动时核对的目标 base。
3. WorkBuddy 自己的 `feat/achievement-qte-ui`：UI/资产，仅消费稳定数据接口；视觉评审单独 PR。
4. 集成时由 Codex/维护者明确执行顺序：先剧情规则与事件 schema，再成就后端，再 UI/QTE，再结局；处理冲突前更新双方 base，不在无确认时自动 merge。
5. 每个 PR 描述必须包含：基准 SHA、修改范围、验收证据、已知缺口、是否影响公开部署、是否需要费用。
