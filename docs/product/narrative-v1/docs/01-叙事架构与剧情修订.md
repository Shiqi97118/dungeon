# 01｜混合叙事架构与 PR #5 剧情修订清单

## 设计目标与边界

- **四层并行故事**：`world`（世界主线）、`regional`（地区冲突）、`personal`（角色个人史）、`sandbox`（玩家自创事业）。每层可以存在、暂停、转折或终结；不得把四层任务都投射为寻找钟心。
- **世界是模拟的，叙事是选择性呈现的**：存档记录世界实际状态，AI 只渲染玩家合理可知的部分。允许“世界发生了，但玩家不知道”。
- **情感前置**：每个关键抉择需要至少一个具体承受影响的角色或地点，不能只给加减分。重大角色有欲望、恐惧、底线、改变信念的证据。
- **无强迫主线**：玩家可开酒馆、做雇佣兵、隐居、成为商会盟友或反叛者；危机通过传闻、利益、地区后果接触玩家，而不是瞬移到玩家面前。

## 状态架构（建议）

1. `worldFacts`：已证实世界事实，含 ID、发生时间、来源事件、不可逆级别、可见范围。不可被 AI 改写；剧情需要改变时要产生**新事件**，不覆盖旧事实。
2. `knowledge`：每个人/势力/队伍分别知道什么、凭什么知道、何时得知；防止 NPC 瞬间全知。
3. `npcs`：每人三部分：`recentImpressions`（最近 3 件）、`milestoneMemories`（永久重要事件）、`beliefs`（信念方向和证据）。好感不等于政治立场。
4. `factions`：计划、阶段、资源、压力、关系、内部派系；每轮按条件递进而不是机械按世界时钟表强制成功。
5. `regions`：经济、治安、人口、控制权、主要设施、地图状态、开放任务。
6. `playerProjects`：玩家自创的酒馆/组织/商队/村庄/誓言，带创建者、资源、阶段、联系人、风险、相关事件。
7. `activeArcs`：类型、目标、玩家兴趣、进度、待解决冲突、休眠状态、必须兑现的伏笔；个人线与沙盒线不得被“最多 8 条”硬性挤出。
8. `eventLog`：追加式唯一事件 ID、角色、地点、观测者、行动与经程序确认的后果；成就/编年史/QTE 都监听同一条事件流。

## 四类时钟的取舍

- 世界危机：全局极少数不可逆节点，如全大陆钟鸣；受重大战争/仪式影响，不宜每 4 轮固定推进。
- 地区时钟：粮价、叛乱、疏散、灾难、公共资源，以不同地区独立推进；能够被玩家事业与行动影响。
- 势力计划：首领目标、准备条件、资源约束、可能的替代方案和失败分支；**满足条件才改变事实**。
- 个人/事业进度：玩家追踪的目标及承诺，时间流逝会影响但不能预写成功与失败。

## 故事推进伪流程

`player intent → permission/safety → world precondition → optional interaction → deterministic check/roll → proposed event → invariant validation → commit event/state → achievement evaluation → AI consequence narration → safe text selection → UI rendering`

- 预写文案不能在 commit 之前宣告结果；事件先发生，AI 再解释。
- 同一自由意图可以触发 0 或 1 个主要叙事互动，避免“叙事互动套娃”和多次消耗 AI 请求。
- 任意具体方案不必映射预设四选一；可通过受控的通用意图/后果类型产生新路线，重大新增事实须审核机制。

## 文本触发的“硬门槛”新增字段

```yaml
id: GH-SCN-09
kind: scene
requires: [location:gray-harbor/copper-tower, invitation_received, banquet_active, attendees_available]
forbids: [tower_destroyed, banquet_cancelled, party_in_combat]
soft_tags: {night: 2, intrigue: 3, merchant_relation_positive: 1}
reads: [region.gray_harbor, npc.cedric, faction.copper_guild]
writes: []                  # 文本本身不能写世界事实
once: per_event_instance    # 不是单纯永远一次
priority: 5
```

- `reads` 不应自动泄露给主人公；仅用于**验证**和**选择**。
- 文本硬条件不足时宁可使用中性过渡，由 AI 在确定事实的边界内补写。
- 对无条件必须播放的文字也做后置状态一致性校验；关键台词应先确认人物可出场且知道该事实。

## 示例：灰港同时支持三种故事

- **冒险线**：调查私井 → 获取证据 → 公布/交易/替换诊所/其他可信方案 → 城市状态变化。
- **生活线**：经营七灯酒馆 → 招募员工 → 建立难民救助互助网 → 灰港政治和难民潮影响业务 → 可在此结束地区故事。
- **逆转线**：协助商会/成立独立组织/政变 → 领袖计划变化 → 资源与城市控制权变化 → 结局分别回顾世界、事业、角色。
- 支持玩家在三条线之间任意转向：通过**事件事实**接续，不通过硬编码剧情跳转。

## 结局三轴与 20 方向兼容

1. `worldResolution`：从经过事实检验的 20 个方向候选中选 0–2 个，或未决/地区级状态；任何灾难方向都需要硬性前提。
2. `playerLegacy`：玩家自建事业、救下的地区、社会影响；可选择未成名/地方传说/大陆传说，基于实际证据。
3. `characterEpilogues`：每个角色的动机与承诺、重要 NPC、遭遇的代价和选择；不得虚构未发生的行动。

### 结局时机

- **队伍自愿收束**：满足参与角色的有效选择规则后，可结束“这支队伍的冒险”，世界主线仍可未决；结局按已知事实生成。
- **世界危机**：若事件达到不可逆危机，可在游戏中成为新的局面/章节，不必强制所有角色剧情全部结束。
- **世界终局**：只在世界层前提满足、玩家确实参与/触发该结局时生成；终局仪式接入微交互。
- 第 0 档可见方向保持 2/20 的数量要求，但 D02 无前提不能强行出现；可以将 2 个方向定义为地区收束变体而非灾难保底，须与用户已定的 20 方向兼容后决定是修词还是调整解锁语义。

## 验收案例

1. 连续 31 次毫无变化地休息，不能达到终局；真实经营行动达到标准可结束地方传奇。
2. 玩家从未去钟城，仍能完成有意义的个人沙盒线、获得本地结局/编年史。
3. NPC 已死/被囚不会被预写文本正常召回；知情范围不同不会出现全知台词。
4. D02 无灾难事实时不得抽中；D17 无门/钟心前提不可实现。
5. 四人中一人晚加入后不会把队伍永久锁死；同样选择/seed 的确定性引擎重放一致。
