# 09｜剧情文本与触发规范

> 目的：不让游戏变成“选择模拟器”。玩家的每一次选择之间，都要有旁白、对话、环境描写和承上启下的文字把它们连成一个故事。本文件规定这些文字怎样写、怎样被“模糊触发”、怎样保证一局之内不重复，以及插图如何与文字同步。文本本身在 `docs/story/text/`，插图计划在 `10-插图计划.md`。

## 1. 文本的种类

| 代号 | 种类 | 作用 | 用法 |
|---|---|---|---|
| ENV | 环境 | 到达一个地区或地点时的景象、声音、气味 | 朗读（原文展示） |
| SCN | 场景 | 进入某个具体场所或局面时的描写 | 朗读 |
| BEAT | 剧情节拍 | 核心冒险的起因、发现、转折、抉择、结果 | 朗读，结果类可由 AI 接续 |
| DLG | 对话 | 人物的台词：初见、按态度分档、失言、转折时刻 | 台词（AI 可拼接，但不得改写关键句） |
| BRG | 承上启下 | 一个场景结束、下一个开始之间的过渡；幕与幕之间的过渡 | 朗读 |
| TRV | 旅途 | 出发、途中、抵达前的文字 | 朗读 |
| RST | 休整 | 扎营、夜宿、同伴闲谈 | 朗读，后接玩家行动 |
| CLK | 世界事件 | 大势时钟升格时的消息与异象 | 朗读 |
| END | 结局开篇 | 20 个方向的“门前”与“第七声”底稿 | 素材（AI 依实际进展改写，保留核心画面） |

**用法说明**：
- **朗读**：原文展示给玩家，只替换占位符。
- **台词**：人物说出的话。AI 可以在前后加入动作和补充，但标有【关键句】的句子必须原样出现。
- **素材**：AI 必须保留文中的核心画面和意象，其余按局势改写。

## 2. 条目格式

```
#### GH-ENV-01 雨夜码头
- 触发：必：地点=灰港；软：夜+2，雨+2，时钟≤3 +1
- 图：GH-01
> 正文……
```

- **编号**：`地区-种类-序号`。地区代号：GEN 通用、GH 灰港、KV 卡尔维斯、WP 白砾、SL 银叶、QZ 栖钟、EM 烬原、SS 沉默海、NC 空名之城、ED 结局。
- **触发**：分为“必”（硬条件，必须全部满足）和“软”（模糊条件，各带权重）。
- **图**：同时展示的插图编号（见 `10-插图计划.md`），可省略。
- **共用**：标有“共用：A / B”的条目可以出现在几条不同分支里，但一局只出现一次。
- **占位符**：`{角色}` 当前行动者的名字；`{同伴}` 随机一名在场同伴；`{队伍}` 队伍的称呼（默认“你们”）；`{纪念物}` 当前行动者的纪念物；`{钟心数}` 队伍当前持有的钟心数（中文数字）；`{到访之声}` 按到访顺序列出已到访地区的“声音”（见第 5 节母题）。`{钟心去向}` 一句话说明不在队伍手里的钟心（已毁或被谁持有，只写队伍已知的），全部在手时省略。`{收束之地}` 队伍收束时所在的地区名（只用于 ED-01B）。`{事业名}` 玩家给事业起的名字（没起名时用事业类别，如“互助站”“酒馆”）；`{事业联系人}` 事业登记的本地联系人（`12` 第 6.3 节）。占位符清单以词表 `placeholders` 为准。其余内容不留空。

### 2.1 接口字段（预写剧情与程序之间的约定）

预写文本只是“在什么条件下展示什么文字”。为了不让文字写出存档里没有发生的事，每段可能涉及事实的条目都带下面五个接口字段。字段写在条目头部（尚未迁移的地区文件暂时写在末尾的“接口表”）。条件与后置的正式写法、行需知、说明、兜底字段见 `12-开工规格.md` 第 3 节，用 `node docs/story/tools/check-texts.mjs` 检查。

| 字段 | 含义 | 由谁执行 |
|---|---|---|
| 可触发（requires） | 硬条件：地点、幕、节拍、人物在场、事实与标记。即原来的“必”。 | 程序过滤 |
| 禁止（forbids） | 只要成立一项就不展示：人物已死亡 / 被抹去 / 不在场、事实已被推翻、同一事实已由别的条目揭示等。 | 程序过滤 |
| 需知（knows） | 这段文字默认玩家已经知道、或已经发生的事实。展示前程序核对存档里这些事实都为真；不为真就视同不满足“可触发”。 | 程序核对 |
| 后置（effects） | 这段文字所对应的变化，分两类：①**事件后果**（地点被毁、关系变化、物品得失、倾向分）——必须先由行动结算并写入存档，文字才可展示，文字本身不改变世界；②**知情**（队伍由此得知的真相证据、暗线揭开、节拍推进）——在文字展示后写入。**后置只能写这里列出的项**。 | ①规则结算 ②程序写入 |
| 交互（interaction） | 可选的叙事微交互模板编号，用设计包 `docs/03` 的六种模板：`memory-assembly`（操作记忆、拼合地图或残片）、`resonance`（共鸣、辨认声音）、`mechanism`（机关）、`evidence`（摆证据、对质）、`dialogue-gesture`（交涉时的态度与姿态）、`crisis-action`（危机中的抢险、撤离）。默认为“无”。交互一律可跳过，跳过时按普通检定结算；失败不得造成永久损害。 | 后续实施 |

**默认禁止**（所有条目都适用，不必逐条写）：已写入 `usedTexts`；DLG 的说话人不在场或已死亡 / 被抹去；条目提到的地点已在“地区收束”中被毁或封闭（`02` 第 11 节）而条目不是余波版本。

**读写边界**：
- 预写文本**只读**存档中“可触发 / 禁止 / 需知”里列出的项和占位符；**只写**“后置”中的知情类项。读到的项只用来过滤和选择，不因此把队伍不知道的事写进文字。
- 文字中出现的任何“已经发生的事”，必须在“需知”里，或在本条的“后置”里；两者都不在，就是穿帮，校验时报错。
- AI 在同一回应里写的叙述不得与“需知”矛盾，也不得声称“后置”以外的世界变化已经生效；AI 想改变世界，只能提出提案，由程序按 `07` 的规则确认后写入。
- **行级需知**：抉择节拍里的每一个选项可以带自己的需知；不成立的那一行不展示，AI 也不提起它。其他条目中个别句子依赖某事实时，接口表写明“不成立时改写或删去哪一句”。
- **必用节拍被排除时**：某节拍按规定必须展示，但所有候选都被“禁止”或“需知”排除，AI 按该节拍的作用现写一段（同样不得越过读写边界），记入缺口日志。
- 没有任何事实含义的纯氛围条目（多数 ENV、BRG、TRV、RST）可以省略五个字段，只保留“触发”。

**三条节拍规则**：
- **结果类节拍**（节拍=结果）只在对应的结果事件已经写入存档之后展示；它是对已发生之事的描写，不能用来决定结果。
- **抉择类节拍**（节拍=抉择）只写冲突、代价和眼下看得见的几条路，结尾必须留出“别的办法”的口子；它不是封闭的选项清单，玩家的自由输入始终可用，AI 的三条建议也不必与文中的路一一对应。
- **交互的数量**：同一个自由意图最多触发 1 个主要交互；T1（轻量）交互每段冒险 1–3 次，T2（关键）交互每段核心冒险最多 1 次；关键台词（DLG 关键句）不挂交互。

## 3. 模糊触发（规则，由程序执行）

### 3.1 情境标签

程序每轮根据存档和本轮行动生成一组情境标签：

| 类别 | 标签 |
|---|---|
| 时间与天气 | 黎明、白天、黄昏、夜、雨、雪、雾、风暴、晴 |
| 地点 | 地区、具体地点、室内、室外、地下、水上 |
| 进度 | 幕 1–4、时钟值、真相层级、已到访次数（首次 / 再访）、钟心数 |
| 人物 | 在场人物、某人物态度档（≤−2、−1…+1、≥+2）、某人物状态 |
| 暗线 | 某暗线状态（未触及 / 有线索 / 已揭开 / 已爆发） |
| 队伍状态 | 受伤、疲惫、补给少、刚战斗、刚交易、被追捕、有人遗忘症状 |
| 行动意图 | 调查、交谈、潜行、战斗、交易、欺骗、帮助、仪式、休息、记录、离开、其他 |
| 行动情绪 | 谨慎、鲁莽、温柔、愤怒、悲伤、幽默 |

**行动意图与情绪由 AI 判断**（玩家写的是自由文字，AI 把它归为最多 2 个意图和 1 个情绪），其余全部由程序从存档中算出。这就是“模糊触发”：条目不匹配玩家写的具体字句，而是匹配这次行动“像什么”。

### 3.2 打分与选择

1. 过滤：去掉“必”条件不满足的条目，去掉本局已用过的条目。
2. 打分：把命中的“软”标签权重相加。
3. 阈值：分数 ≥ 3 的条目进入候选；BEAT 与 CLK 只看“必”条件，不需要分数。
4. 选择：取最高分；同分时用本局随机种子挑一个（可复现）。
5. 记录：被选中的条目编号与轮次写入存档 `usedTexts`；能否再次出现按第 3.4 节的复用规则判断。

### 3.3 每次回应能用多少预写文本

| 时机 | 预写文本 |
|---|---|
| 剧情节拍、时钟事件、幕转换 | 必用对应的 BEAT / CLK / BRG，各 1 段 |
| 到达地区、进入地点 | 1 段 ENV 或 SCN |
| 人物首次登场 | 1 段该人物的 DLG“初见” |
| 普通行动 | 最多 1 段（ENV / SCN / DLG / RST），没有候选就不用 |
| 场景结束、换地点 | 1 段 BRG 或 TRV |

预写文本永远放在 AI 叙述的固定位置：先 AI 写行动结果，再接预写文本，最后是三条建议。插图在预写文本展示时同时出现。

### 3.3a 节奏：每一屏的最少内容（用户要求“不要一句话就跳转”）

- **一屏**指玩家点“继续”或做下一次选择之前看到的全部文字。
- 每屏至少两段：AI 写的行动结果 + 至少 1 段预写或现写的环境、人物反应或过渡；合计不少于 180 字。AI 叙述本身仍为 120–250 字（`07` 第 2 节）。
- **换场景用三段式**：收尾（这里发生的事有了什么余音）→ 过渡（BRG 或 TRV，路上或时间流逝）→ 进入（新地点的 ENV 或 SCN）。三段可以分两屏展示，但不能只用一句“你们来到了某地”带过。
- 场景至少持续 2 轮，除非玩家主动离开或被局势逼走。
- 文字展示后**不自动跳转**：由玩家点“继续”翻页；多人模式中每名玩家各自翻页，不影响他人的回合。（界面行为是开发事项，见 `08` 第 5 节 6b，本 PR 不改代码。）
- 预写文本不足时，AI 现写补足到上述下限，计入缺口日志。

### 3.4 不重复与回退

- **复用规则**（用户 2026-11-11 同意按设计包的建议调整；原“所有文本一局只用一次”不再适用于 ENV / RST / TRV）：

| 类别 | 一局之内 |
|---|---|
| BEAT、DLG（含关键句）、BRG、CLK、END | 只出现一次 |
| SCN | 每个事件实例一次（同一场晚宴只播一次；剧情真的再办一场时才可以再播） |
| ENV、RST、TRV | 可以冷却后复用，三个条件同时满足：距上次展示 ≥ 20 轮；当前情境里同类的未用候选已经用完；同一条目一局最多出现 2 次 |

  复用时意思必须和当前状态一致：条目的“必”条件照常检查；状态已经变了（地区进入动荡、天气或时段不同、人物不在了），AI 在条目后补一句交代变化，不改条目原文；与当前事实冲突的句子不能复用，改由 AI 现写。不同分支可以共用一段过渡。
- **用尽时**：某类候选全部用完或没有命中，AI 按第 5 节的风格卡现写一段，同类内容在本局也不能重复（AI 收到最近 30 段已用文本的摘要以避开相似内容）。现写的条目记入“缺口日志”，供后续补写。
- **不同局之间**：允许重复；但同一局的随机种子不同，模糊触发会让不同局看到不同的组合。

## 4. 文本数量要求

按最长一局（约 80 轮、到访全部地区、多次往返）估算，每类至少要准备：

| 种类 | 一局最多用到 | 本批已写 | 说明 |
|---|---:|---:|---|
| 开场 BEAT | 1–2 | 6 | 标准、单人与四条钩子 |
| 幕转换 BRG | 3 | 6 | 每次转换两个版本 |
| 通用场景过渡 BRG | 约 30 | 32 | 含 3 条兜底条目 |
| TRV 旅途 | 约 14 次旅途 × 2 段 | 通用 18 + 路线 18 | |
| RST 休整 | 约 10 | 12 | |
| CLK 世界事件 | 12 + 全面危机 | 24 + 6 | 每格两个版本（默认 / 势力已被改变） |
| 地区 ENV | 首访 + 至多 3 次再访 | 39（每地区 3–4；灰港另有 8 段玩家事业） | |
| 地区 SCN（含支线开场） | 主要地点各 1 | 75（每地区 6–11；灰港另有 14 段玩家事业与风险事件） | |
| 核心冒险与终局 BEAT | 每段 5 个节拍 + 结果 | 75（每段 9–11） | |
| DLG 台词 | 核心人物初见与分档台词 | 132 句 | 37 位人物 |
| END 结局开篇 | 1 主方向 + 1 副方向 | 21 | D01 分远行、落地两版 |

本批共 464 段（按 `text/` 目录逐条统计）。一次性类别足以支撑最长一局；ENV / RST / TRV 按第 3.4 节冷却复用，仍不足时由 AI 现写，并持续扩写。

## 5. 风格卡（给写作者和 AI）

- **语气**：翻译过来的西方奇幻。句子可以长，但每段只写一个焦点。
- **感官**：每段至少有一种视觉以外的感觉（声音、气味、温度、触感）。本作的核心是声音，优先写声音。
- **长度**：ENV / SCN 70–200 字；BEAT 70–260 字；BRG / TRV / RST 85–220 字（通常两段：一段收住刚才的事，一段把人送往下一处）；CLK 100–240 字（消息 + 街头的反应）；DLG 每句不超过 60 字。单段条目再短，也要与 AI 叙述一起满足第 3.3a 节“每屏不少于 180 字”。
- **留白**：不替玩家角色决定感受；不把线索答案写进描写；描写可以暗示，结论留给玩家。
- **母题**：钟、回声、名字、雾、铜、灯。每个地区有自己的“声音”：灰港是雨和讨价还价，卡尔维斯是钟楼和盔甲，白砾是滴水和回声，银叶是树叶的重复，栖钟是整点钟鸣，烬原是鼓和熔岩，沉默海是没有声音，空名之城是自己的名字在消失。
- **禁止**：现代网络用语、中式古风称谓、现有作品专有名词、血腥细节。

## 6. 文本与插图同步

- 每段 ENV、SCN、BEAT 尽量配一张图；DLG 首次出现时配人物肖像。
- 插图的触发条件与文本相同：文本被选中时，配图同时显示；没有配图的文本沿用当前地点的场景图。
- 同一地点的插图按局势有“变体”（例如灰港平静 / 骚乱后），由存档状态决定显示哪一张。
- 插图只表现氛围，不暗示线索答案（沿用 `docs/module/07` 的原则）。

## 7. 一段完整的回应示例

> 玩家行动（芙蕾雅）：“我在码头上找那个咳嗽的老人，问他去过商会的免费诊所没有。”
>
> 程序：意图=交谈、调查；情绪=温柔；地点=灰港·低潮街；夜；雨；暗线一=未触及 → 选中 `GH-SCN-03 低潮街的病人`（分数 5），配图 GH-04。
>
> AI 写结果：老人起初不肯开口，直到芙蕾雅蹲下来替他把湿透的围巾拧干……
> 预写文本：（GH-SCN-03 原文）
> 三条建议：……
