## 1. 存档兼容（高风险，须先于任何数据结构改动定案）

### 1.1 现状

- `engine.ts:19` `SAVE_VERSION = 4`；`engine.ts:25` `newGame` 写入 `version`。
- `App.tsx:20-29` `loadSave()`：`s.version === SAVE_VERSION ? s : null` —— **版本不等即静默丢弃**，无迁移、无提示。
- `App.tsx:66-68` 单人存档写 `localStorage['echo-well-save']`；`App.tsx:110-129` `resume`/`restart` 依赖 `saved`。
- `server/rooms.ts:184` 房间 `RoomData.state` 直接存 `newGame(party, …)` 的结果，随房间持久化；`view()`(:63-75) 把整个 `state` 下发给客户端。
- 导出：`endings.ts:107-141` `buildArchive` 生成 Markdown；`src/ui/Ending.tsx:58,92,105-109` 提供下载 / 复制（**该文件未读**，需核对）。

### 1.2 目标

1. 新增 `migrateSave(raw: unknown): GameState | null`，按 `version` 分派：
   - `v4 → v5`：`job`/`ancestry` 置 `null`（或按 `title` 反查，见风险）、`jobMarkUsed=false`；`hooks` 由 `party[].hook/memento` 生成 `{state:'laid'}`；`ITEM_USE` 由 `items` 派生；其余字段原样保留。
   - 未知 / 更高版本：返回 `null` 并提示「存档来自更新版本，请升级客户端」，**不静默丢弃**。
2. `App.tsx:25` 改为调用 `migrateSave(parsed)`；`Title` 的「继续」按钮对不可迁移存档显示原因（需核对 `Title.tsx`）。
3. 联机房间：`RoomData` 增 `protocol` 版本；`rooms.ts` 读取旧房间时按同规则迁移或返回 409 提示重建房间，避免 `state` 缺字段导致 `view()` 下发 undefined。
4. `buildArchive` 增输出：`hooks` 三态、职业 / 种族贡献、道具消耗记录；导出格式变更需向后兼容（旧解析按标题行读取）。
5. **顺序约束**：先实现并测试 `migrateSave`，再升 `SAVE_VERSION`。否则现有 v4 存档与进行中的联机房间全部失效。

### 1.3 风险

| 风险 | 说明 | 缓解 |

| `title` 反查职业不可靠 | 现有 `CharacterBuilder.tsx:22` 把 `ancestry + ' · ' + job` 拼进 `title`，预制角色 `title` 是「前矿工」等，格式不统一 | v4 迁移**不反查**，置 `null` 并在 UI 提示「旧角色未指定职业，可补选」 |
