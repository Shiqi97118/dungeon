# 02｜成就、图鉴与冒险者编年史｜完整产品设计 V1

## 1. 目标与原则

- **目的**：承认玩家的创造性与有意义的选择，帮助复盘/重玩，而不是强迫玩家刷任务。
- **首版完整内容**：50 个静态成就（`../data/achievements.v1.json`，条目含 ID、名称、展示文案、分类、稀有度、scope、hidden、可核验规则、图标、奖励）；另有**动态传奇事迹**，它们不是额外的静态成就数量。
- **成就归属**：全局账户收藏跨局保留；本局/角色/队伍的事实与归因独立存档；多人队伍成就和个人成就必须区分。
- **奖励**：成就徽章、称号、装饰边框、可回顾故事卡、编年史插页；**不直接提供游戏属性、倾向分、NPC 好感或骰子加成**。
- **公正**：不偏好战斗、屠杀或倒向某个势力；提供外交、日常经营、辅助、探索等多样达成方式。

## 2. 五大分类与首版数量

| 类别 | 前缀 | 数量 | 基础图形 | 分类主色 |
|---|---|---:|---|---|
| 剧情与世界 | ST | 12 | 钟、卷轴、盾 | 铜金 `#C4A16B` |
| 人物与关系 | RE | 10 | 双手、心、纹章 | 玫瑰金 `#D59AA5` |
| 探索与发现 | EX | 10 | 罗盘、星、古钥 | 天青 `#7FB5CC` |
| 沙盒与创造 | SB | 8 | 城堡、交易、羽笔 | 苔绿 `#8CB89A` |
| 隐藏与传奇 | LG | 10 | 王冠、七星、破钟 | 紫金 `#BC9CEA` |
| 合计 | — | **50** | | |

稀有度 `common` / `rare` / `epic` / `legendary` 仅影响装饰和回顾，不与秘密程度绑定。隐藏规则由 `visibility` 独立控制：`public`（显示）、`hint`（只显示提示）、`secret`（达成前连名称、图标都隐藏）。静态隐藏成就总数量在总进度中计数，详情不可泄露；类别统计可见但无剧情剧透。

## 3. 图标资产交付

- 该包 `assets/icons/svg/` 有 50 个**独立 SVG 矢量图标**；`assets/icons/png/` 有对应 128×128 PNG；预览 `assets/icons/成就图标总览.png`。
- 风格：暗蓝/煤黑底 + 古铜双圈 + 中央独特符号；分类点缀色保持一致。不得把 `iconKey` 当成远程 URL；只允许白名单本地资源。
- 适配：主界面 48px（移动端 44–56px）、详情 96px、Toast 48px、结局 64px；SVG 使用 viewBox 0 0 128 128；PNG 高 DPI。
- `locked` 状态：灰度、降低亮度但**不能完全用颜色表达锁定状态**；另有小锁形或“未解锁”文字。`secret`：使用统一占位图，不暴露图形轮廓和真实名称。
- 当前图标为**可直接使用的首版 SVG/PNG 设计资产**，并非已由 Cursor 合并的游戏资源；采用透明/暗底式需在实际 UI 主题中测亮暗模式可读性。

## 4. 成就规则与事件源

- 规则只处理**经过引擎验证后提交的 canonical event**。AI 可以提议 `candidateAchievement`, 但没有执行权限。
- 事件必须含 `eventId`、`runId`、`seq`、`type`、`actorIds`、`partyIds`、`subjectIds`、`payload`、`committedAt`、`schemaVersion`；多人服务器持久化在同一事务中提交事件，再**幂等**执行成就解锁。
- 规则 DSL：`event`（事件+where）、`all`、`any`、`count`、`distinct`；默认同一次 `runId` 内求值。详情见 `contracts/narrative.types.ts`、`docs/05`。
- 服务端权威：线上房间不可接受客户端自行上报“已达成成就”；微交互提交的是操作意图/结果证据，由服务端验证发出 canonical event。
- **不能靠 AI 叙述字面匹配解锁**，也不能靠某个 UI 页面显示次数解锁。
- 首次解锁持久化账户级，之后同一次成就不重复弹窗；仍应保存每局完成记录以便结局页统计。

## 5. 解锁顺序

`事件提交成功 → 校验规则 → 得出新成就 ID → 创建 UnlockRecord → 写入用户收藏/本局解锁 → 更新编年史引用 → 加入通知队列 → UI 渲染`。

若事件同时触发多个成就：原子性计算，按 `legendary > epic > rare > common` 排列，队列逐个播报，最多连续自动弹出 3 个，其余折叠成“另有 N 项已解锁”；用户可以在图鉴找到全部。

### 失败、重试、回退

- 离线暂存：标记 `pendingSync`，UI 可以展示“本地待同步”，不能谎称服务器永久成功。
- 网络重试：使用 eventId 幂等，不重复奖励或弹窗；服务器确认后才改 `verified`。
- 历史存档：若 `SAVE_VERSION` 升级导致旧局不可继续，账户级成就仍应保留；导入迁移需要单独验真，不直接信任本地 JSON 生成解锁。
- 退出房间：已获个人成就不受队长是否继续影响；没有参与的玩家不获个人贡献奖。

## 6. 主界面：成就图鉴（完整体验）

位置：标题页“成就”独立入口（或游戏大厅“成就”页签），联机游戏中也可从暂停菜单打开但**不得抢占主持人回合**。主界面为单屏：左边分类筛选（手机顶部横向切换），右边内容格子及细节；不采用整页反复上下滚动，成就区域内部滚动/分页。

- 顶部统计：`已解锁 12 / 50`、百分比（包括隐藏数量）、最近一次解锁、传奇次数（独立计数）。
- 筛选：全部/剧情/人物/探索/沙盒/传奇；解锁状态：全部/已获得/未获得；稀有度；排序：默认/最近/稀有度/分类。
- 组件：16:9 桌面 4～5 列；窄屏 2 列；每项显示图标、可见名称、稀有度、状态。长描述在详情抽屉，不挤占卡片。
- **未获得公开成就**：展示完整名称、目标和可公开的进度。**Hint**：只显示暗示，不展示准确条件或未发现人物。**Secret**：`???`、遮罩统一图标、无提示/图透。
- 详情：icon 96px、名称、分类、稀有度、说明、条件是否公开、`n/m` 进度或“探索中”、解锁日期、来源角色/队伍、对应编年史章节、可选“设置称号”。
- 进度栏只针对公开明确可计量的成就（例如到访 7 地区）；复杂历史条件不要显示虚假百分比。
- 图鉴中全部素材从本地 achievement definitions 生成，不让 AI 改名称或新增任意代码。动态传奇事迹进入另一页签“编年史”，审核通过后可作为收藏卡。

## 7. 解锁提示：Toast + 详情弹窗

默认是非阻断的**成就 Toast**：

- 位置：桌面右上、移动端顶部安全区下方；绝不遮住输入框、正在使用的按钮、掷骰、QTE 中心或字幕。
- 默认显示 `成就解锁`、图标 48px、名称（若已解锁自然可见）、分类/稀有度、简短一句话；4–6 秒自动消失，鼠标悬停/键盘聚焦时暂停。
- 点击 Toast 打开**成就详情弹窗**；弹窗可通过关闭按钮/ESC/点击遮罩关闭，回焦到原元素；禁止因为新通知夺走焦点。
- 优先级：进行中的 QTE/骰子/角色安全确认/阅读分页时只**入队**，待这些 UI 结束后展示；终局动画期间可先累计，结局页集中展示。
- 音效：可选轻微铜钟+短闪光；无障碍 `prefers-reduced-motion` 下无弹跳，无音效/关闭效果可配置；屏幕阅读器 `aria-live=polite`。
- 并发：若短时间 4 个以上，不用每个都遮屏，自动折叠“获得 5 项新成就”可查看列表。
- 解锁弹窗（用户主动打开）：最大宽桌面 520px、移动占屏 90vw、高度自适应且内容区域内部滚动；内容包括描述、纪念时间、达成证据简述、编年史跳转、隐私分享开关；永远提供关闭按钮。

## 8. 结局界面：成就进度与回顾

顺序：`结局演出 → 世界/事业/角色三轴尾声 → 本局成就总结 → 关键事迹时间线 → 完整图鉴入口`。

- 顶部：`本次新获得 A 项`、`本局达成 B 项（包括此前已解锁）`、`永久总进度 C/50`。
- 两条进度不可混淆：**永久收藏进度** `C / 50`；**本局达成数量** `B` 不用 `B/50` 误导。
- 本局新得列表按稀有度和事件顺序展示；“此前已获得但本局再次达成”作为次要列表，避免重复领奖。
- 未获得概览按类别显示“已获得 X / 该类总数”，隐藏项目仍不得泄露名称或图片。
- 编年史：最多展示 5 个经过事实校验的重大事件+玩家亲手创造的组织/承诺；提供下载/复制纯文本存档（去除账号敏感信息、密钥与私密聊天内容）。
- 动态传奇事迹与静态成就分区：前者带 **“本局事迹”** 标识，不纳入 50 的分母。
- 联机：展示队伍共同成就与“我个人”两个标签；队伍结局不能擅自公布他人私密角色历史。

## 9. 编年史与世界传说

- `ChronicleEntry`：包含世界事实引用、事件因果链、涉及角色、地点、影响范围（小队/地区/大陆）、证据等级、AI 文案版本、可见性。
- AI 可提出标题与叙事描述，程序检查事件是否真实、是否可公开；不可把未经发生的事写进历史。
- 特殊例子：玩家建立了救援组织后促成停战，生成“无冠的守护者”世界传说卡；可在**本局**地图/书籍中留痕。
- **不同周目之间不得污染正史**：除非明确设计为跨世界传说/大厅展示，否则上一局创造的纪念碑不能凭空出现在另一局的同一世界。可以在账号级“传说馆”统一回顾历史；未来如做跨局世界继承，需独立授权及规则。

## 10. 设计验收

1. 50 项数据都有唯一 ID、可渲染图标、准确规则/隐藏政策、非数值奖励；JSON 通过静态校验。
2. 同一事件重放 100 次只解锁一次；跨账号不会串档；断网重连不丢解锁。
3. 未完成前隐藏的“皇帝归来”类成就不可通过图鉴名称、icon 或进度剧透。
4. 同时多项解锁不覆盖 QTE/阅读/骰子；Toast 支持键盘、静音、减少动画。
5. 结局页区分本局与永久解锁，统计准确；中途退出的玩家不会得到未参与的个人成就。
6. 玩家使用自由方案解决潮井事件，可以在有可信证据时解锁“另一条道路”，但 AI 任意夸奖不能解锁。
