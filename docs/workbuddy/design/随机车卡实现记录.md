## 二、设计要点（在现有轻量规则内）

- **完整随机、不只随机姓名**：`randomDraft()` 一次产出姓名、12 职业之一、8 种族之一、`+2/+1/0/-1` 各分配一次的四属性、两项互异且来自白名单的专长。
- **常量单一来源**：`JOBS`/`ANCESTRIES` 从 UI 抽到 `characterDraft.ts`，UI 与测试共用，避免重复枚举；专长白名单由现有 `SPECIALTIES` 派生，不另抄清单。
- **装备沿用现有合法生成器**：`draftToCharacter()` 与 `randomPlayableCharacter()` 以 `randomCharacter()` 的结果为基底，保留其 `ITEMS` 随机装备、`id`、动机、钩子、纪念物、符印、`reason`、`stress` 等，再覆盖表单字段。未新写装备表，未引入新素材。
- **与旧随机组队入口兼容**：`Setup.tsx` 的 `addRandom` 仍直接调 `randomCharacter(pool.map(...))`，未改动、未重构引擎与联机协议。
- **不新增未经实现的职业加成**：`title` 仍为「种族 · 职业」纯背景文本，职业/种族不参与 2d6 数值计算，与改动前一致。
- **可微调可保存**：随机结果填入同一套表单 `state`（姓名/职业/种族/属性/专长），玩家可改后用「保存角色并加入队伍」；「直接加入」一步生成完整合法角色并 `onAdd`。
- **校验集中**：`isDraftValid` 统一约束姓名非空、职业/种族合法、属性恰为标准数组、专长恰好两项互异且在白名单；UI 禁用态与测试共用该判定。
