# WorkBuddy 协作与验收规范

## 最高优先级原则

派工、执行、设计审核、代码审核和返工必须遵从 [项目核心准则：12 条最高标准](../编程与审核原则.md)。每次验收逐项记录全部 12 条准则的通过、需返工或未验证状态及依据；关键项未验证不得通过。原有待审方案也按此标准复核，不自动扩大实现范围。

## 模型与费用
- 用户确认免费模型 hy4 优先，并允许使用消耗较低的积分模型。必须核对真实模型 ID 与可得的消耗信息，并在派工时明确指定、读回核对。简单任务优先 hy4，复杂任务可使用已确认低消耗的模型。
- 不添加付费 API key，不充值，不自动切换未经核对的付费模型，不用 Codex 自己的子代理冒充 WorkBuddy。
- 免费模型额度不足或能力不足时，可以切换已确认的低积分模型；不自动使用高消耗、价格不明的模型或另行收费的外部工具。不得自动充值。返工沿用相同费用约束。
- 网关不提供积分余额和扣费查询，因此不能承诺技术上已强制零扣费。

## 职责
- Codex：拆分任务、定义范围与验收条件、审核设计与 diff、运行必要测试、核验素材和记录返工。未经实际检查不接受成果。
- 游戏设计 agent：负责车卡规则、探索循环、章节节奏、线索冗余、角色关系与道具的剧情作用；交付具体规则、状态迁移、示例及验收场景。
- 开发 agent：依据已批准设计实现前后端，处理存档兼容、联机权限、错误恢复和移动端；交付代码、测试证据和已知缺陷。
- 美术 agent：负责角色展示、视觉层级、阅读舒适度与素材规范；交付可用于游戏的真实资产、来源/授权说明及实机截图。无免费图像生成能力时只交付规范和低成本矢量方案，不声称已生成插画。
- 这些是待核验的角色分工，不表示 WorkBuddy 已存在对应专业 agent。接入后先列出其实际 agent/skill 能力；缺少时明确创建角色任务，不能虚构插件能力。

## 执行顺序与文件范围
0. 最高优先级使用仓库 `.agents/skills/jiaojie/SKILL.md`：接续先 RECEIVE 根目录 handoff.md，阶段交付按 EXPORT 保存精确停止点、有效决定、废案、失败和未验证。无权修改 handoff.md 时先提供准确交接内容给 Codex 汇总，不越过 allowedPaths。接收回执不是功能验收，历史授权不自动变成当前外部操作权限。
1. 首次连通验收：WorkBuddy 自己在 .local/workbuddy-acceptance/ 写清单，Codex 读取实际文件；同一任务返工后再读；保留 taskId、attemptId、sessionId、runtimeSource 和模型 ID。
2. 游戏设计只写 docs/workbuddy/design/；美术规范只写 docs/workbuddy/art/；设计验收后才派代码实现。
3. 同一代码工作区串行修改，避免多个 agent 覆盖；不得重置或丢弃当前未提交改动。
4. 禁止修改网关、凭据和全局配置；禁止自行 push、发布、部署、购买资源或扩大权限。
5. 每次修改前读过往修改日志，更新当天 YY-MM-DD.md；日志只记录实际完成的内容。

## 质量门槛
- 阅读：回看历史时新增消息不改变位置；继续阅读定位第一条未读消息；长段落、AI 连续行动、加载存档、移动端和语音停止均需实测。
- 车卡：说明职业、种族、属性、技能的具体游戏作用；校验预算和服务端输入；不能只加名称选项就宣称完整规则。
- 剧情：首章让玩家理解目标、工具用途和行动选择；每条个人伏笔必须有可记录的铺设、验证和回收条件。目标体验时长由游玩验证，不通过文本字数或强制等待冒充。
- 联机：先建房/加入，再建卡和准备；房主开局；非房主越权、重复角色、断线重连、旧存档兼容都要验证。
- 美术：角色应有可辨识轮廓与状态，文字不能被视觉效果遮挡；适配手机，提供实机证据。
- 实现：TypeScript 与生产构建通过，相关行为测试通过；不能删除测试、放宽断言或仅报告文件非空。
- 缺陷按严重程度返工：崩溃、越权、丢存档、规则错误为必须修复；未完成项目明确保留，不标完成。
