# 回声井：第七道门 · 网页跑团

基于 `docs/module/` 中的原创模组包制作的网页跑团游戏。单人模式浏览器打开即可游玩；联机模式需要一个小服务端：可以部署成**公开链接**（Cloudflare Workers + D1，免登录），也可以发布到 Cursor（需登录）。

## 玩法概览

- **开团流程**：内容边界与淡化设置 → 选择 1–4 名预制或随机角色 → 填写入团理由与队伍关系 → 接受委托。
- **2d6 轻量规则**：检定前展示属性、专长、情境加值与失败风险；10+ / 7–9 / 6- 三档结果；7–9 由玩家选择代价，可花优势点减轻代价或重掷一颗骰。
- **回声压力时钟 0–6**：深入、拖延、失败会让井“清醒”，触发模组里的世界反应（影子副本、遗忘对话、核心开门），到 6 强制进入终局。
- **7 个地点 + 开场**，访问顺序自由；关键线索有多条冗余来源，失败不会锁死剧情。
- **NPC**：宁芮、乔安、伊芙琳、陆铎各有目标与态度变化；陆铎会带着破岩钻中途追上来。
- **互动谜题**：在水闸礼堂和井底按残谱敲响六口钟，第七音必须由“静默”完成。
- **5 种结局 + 自创方案**：封存、修复（需要一段自愿交出的记忆）、摧毁、交付、撤离；结局后为每位角色记录“带走了什么”，并导出符合模组 06 模板的章节存档。
- **自由行动**：输入框可以写下任何行动。离线时由规则裁定（选属性掷骰，按结果推进线索或付出代价）；配置 AI 主持人后，由大模型依照模组 06 的主持规范即兴叙述，并以受限的结构化指令修改游戏状态。

## 联机与回合制

- 标题页「与朋友联机」：房主选好队伍后得到 6 位房间码 / 邀请链接，朋友加入后**每人认领一名角色**。没人认领的角色由 **AI 同伴**扮演；有人离线超过 45 秒，AI 也会暂时接手，回来后自动交还。
- **先攻**：每轮按「灵巧×2 + 1d6 + 状态修正」排序，轮到谁谁行动，一回合做一件事（预设行动、自由行动、移动、休息或结束回合）。
- **状态**：中毒（先攻 -2，每回合一半几率承压）、昏迷（跳过回合，可被同伴唤醒）、失温、割伤、颤抖、耳鸣、迷失方向、短暂失声，以及大成功带来的「专注」（先攻 +2）。失败时会按地点触发环境危害；短休可解毒止血，扎营清除全部状态，也可以花一个回合「照料」队友。
- 骰子由服务器掷出，全桌同步看到同一组骰子；桌边聊天不会写进故事。
- **AI 同伴**按各自的属性和专长挑选行动：优先唤醒昏迷的同伴、处理危机、照料伤员，其次调查与交谈；它们会自己掷骰、选择代价，但**不会替你们移动队伍或选择结局**。钟序谜题、记忆抉择这类全队决定，交给在场的任意一位玩家。
- 单人模式默认开启回合制：你扮演一名角色，其余由 AI 同伴扮演（也可以选「全部亲自操控」）。

## AI 主持人

- **内置主持人**：服务器读取环境变量 `OPENAI_API_KEY`（可选 `GM_BASE_URL`、`GM_MODEL`）。能认出前缀的密钥会自动走对应服务：`xai-` 用 xAI 的 `grok-4.7`，`sk-or-` 用 OpenRouter，`sk-proj-` 用 OpenAI；其他密钥（如 DeepSeek、通义千问）走 `GM_BASE_URL` / `GM_MODEL`，公开部署里默认是 DeepSeek 的 `deepseek-flash`，密钥不会下发到浏览器。联机房间始终使用它，单人模式默认也使用；未配置时自动回退为离线规则主持。
- **自带密钥（仅单人）**：在「AI 主持人」设置里填写任意兼容 OpenAI Chat Completions 的接口，密钥只保存在本机浏览器，由浏览器直接请求服务商。

## 开发

```bash
npm install
npm run dev      # 本地开发
npm test         # 引擎、回合制与房间 API 测试（设置 TEST_DATABASE_URL 可同时跑 Postgres）
npm run build
```

本地 `npm run dev` 会把 `/api/*` 挂到同一个开发服务器上；没有 `DATABASE_URL` 时房间存在内存里。`npx wrangler dev` 则以 Cloudflare 的方式在本地运行（本地 D1）。

## 部署成公开链接（Cloudflare）

`wrangler.jsonc` 已配置好：Worker 负责 `/api/*`，其余是 `dist/` 里的静态页面，房间存在 D1 数据库 `echo-well` 中（首次请求自动建表）。公开模式不需要登录：每个浏览器有一个随机 ID，用来认出回来的玩家。

1. 打开 Cloudflare 控制台 → **Workers 和 Pages** → **创建** → **导入存储库**，连接 GitHub 并选择这个仓库。
2. 项目名填 `echo-well`；构建命令 `npm run build`，部署命令 `npx wrangler deploy`。之后每次推送都会自动重新部署。
3. 部署完成后，在该 Worker 的 **设置 → 变量和机密** 里添加机密 `OPENAI_API_KEY`。可选：`GM_BASE_URL`（任何兼容 OpenAI 的接口）、`GM_MODEL`。
4. 链接形如 `https://echo-well.<你的子域>.workers.dev`，发给朋友即可。

公开链接谁都能打开，所以服务器对 AI 调用设了上限：全站每天 `GM_DAILY_LIMIT` 次（`wrangler.jsonc` 里设为 1000），每个 IP 每天 300 次，每个房间 600 次。超过后自动改用离线规则主持。

## 发布到 Cursor（需登录）

`cursor-app.json` 声明了 Postgres，表结构见 `migrations/`。这种方式只能设为私有或团队可见，朋友需要登录 Cursor。设置 `ECHO_PUBLIC=1` 可以在任何 Node 托管（如 Vercel，需 `DATABASE_URL`）上改用免登录模式。

目录结构：

- `src/game/`：规则引擎、回合与状态（`conds.ts`）、意图编排（`session.ts`）、场景数据、线索、结局与 AI 主持人协议
- `src/game/companion.ts`：AI 同伴的行动策略，以及服务端与界面共用的「谁能操作」规则
- `server/`：房间、轮询、座位与 AI 主持人代理；`platform.ts` 抽象出身份与存储，`node.ts`（Cursor / Node + Postgres）和 `worker/index.ts`（Cloudflare + D1）分别接入
- `src/net/`：联机客户端与轮询
- `src/ui/`：界面组件（标题、建卡、联机大厅、先攻条、聊天、游戏主界面、掷骰、七钟谜题、结局）
- `src/audio/`：Web Audio 合成的雨声、矿洞环境音、钟声、骰子音效
- `public/art/`：按模组 07 插图提示词生成的场景插图
