# 06｜分阶段实施计划（先设计同步，再实现，最后验收）

> 计划以**依赖关系**而非承诺日期/费用作为进度依据。Cursor 正在修改 PR #5，故不得直接写入它的工作分支。工作前先刷新最新 PR head、读取 AGENTS.md、12 条原则、handoff.md、全部修改日志。每个阶段拆为独立、小范围可验收 PR；不自动 merge/deploy。

## 阶段 0｜冻结范围与同步共识（文档优先）

**负责人建议**：GPT 审核，Cursor 整合剧情，Codex 检查冲突。

- 读取本包 `00` 与全套 spec；重新确认 PR #5 当前 head，生成“旧规则→建议规则”差异清单。
- 标注 `CONFIRMED` / `PROPOSED` / `NEEDS_PLAYTEST`；已确认：世界观、混合型玩法、成就、QTE 方向。待试玩：精确选择计数、各时钟速度、数值权重与触发密度。
- 在 Cursor 当前分支按**最小文本 diff**整合 `02/04/05/06/07/09`，并改对应 `text/` 预写段落。不要从交接包直接覆写这些文件。
- 新文档可纳入 `docs/story/11-成就与编年史.md`、`docs/story/12-叙事交互.md` 或独立 `docs/product/`，但只设一个正史入口。

**验收**：无重复权威规则；冲突表每项有明确结论；PR #5 的源头文件没有被覆盖；仅文档改动，测试如无代码可记“不适用”。

## 阶段 1｜叙事事实账本与规则原型（最优先工程）

**负责人建议**：Codex 主责，Cursor 检查剧情适配。

- 先写 append-only canonical event 和纯函数 reducer；测试事实不可静默删除、重放确定性、NPC 知情边界。
- 设计并通过 `NarrativeProposal` 校验；把 AI 自由行动映射为受限的事件提案，不能直接改世界事实。
- 多类时钟+势力独立计划，仅在经过条件检验时提交状态变化。
- 为旧 `GameState` 做最小 adapter，不要第一步就完全重构所有程序。

**验收**：P0 叙事一致性测试通过；旧单机/联机回归不退化；不会出现两个世界状态的“权威来源”。

## 阶段 2｜成就引擎与 50 项图鉴 MVP

**负责人建议**：Codex 规则，Cursor 集成 UI，WorkBuddy 美术审核。

- 导入本包 `data/achievements.v1.json` 和图标，验证 50 项与资源一一对应。
- 写 evaluator、progress、unlock store、个人/队伍归属、隐藏条件脱敏、幂等、多人服务端校验。
- 新增主界面“成就”入口、图鉴（过滤/排序/详情）、非阻断 Toast。先用游戏已有事件做 5–10 个端到端 smoke cases，完整目录的条件按 staged features 接入。
- `featureFlag.achievements` 默认仅开发环境开启，线上发布必须经过验收与成本/同步检查。

**验收**：数据静态检查全绿；5–10 条真实事件可以端到端解锁；秘密无泄露；重试不双发；图鉴可浏览 50 项并准确区分可用/未实装判定。

## 阶段 3｜六套叙事微交互模板

**负责人建议**：WorkBuddy 视觉/动画，Cursor 接入流程，Codex 验证后果。

1. `evidence`（灰港账本）：最快形成故事体验。
2. `dialogue-gesture`（公主丝带）：验证情感互动与角色同意。
3. `memory-assembly`（失踪者记忆）：验证线索系统。
4. `mechanism`（潮井管道）：验证规则/物品。
5. `resonance`（七钟共鸣）：验证声音/视觉反馈。
6. `crisis-action`（沉默海绳索）：验证宽松时限、跳过、多人。

- 每个模板均有可跳过、键盘与触屏替代动作；交互 `completed` 只记一次事件。
- `09` 预写文本用 `<interactionRef>`（实际语法自行确定）触发，不允许预写后果越过操作直接出现。

**验收**：六模板各至少一条真实剧情接入；无障碍路径可用；离线/联机和断线恢复无重复扣资源。

## 阶段 4｜混合叙事灰港垂直切片

**负责人建议**：Cursor 剧情与游戏联调，GPT 审稿，Codex 回归。

- 同一个灰港支持：追查私井、经营酒馆、自主干预政治三条主线相互转化。
- 测试 31+ 次有意义选择，不能刷无效动作；地方结局与灾难结局区别清晰。
- AI 主持人按 NPC 的事实、长期记忆、价值观与能否知情作出反应；重要文本后果必须先验证再播放。
- 本切片打通“玩家自由行动 → 事件账本 → AI 叙述 → QTE → 成就 → 编年史 → 地区性结局”。

**验收**：5 套压力测试（沙盒、反主线、关键 NPC 死亡、钟心毁损、多人中途加入）全部通过；录制人工试玩记录和 bug 列表。

## 阶段 5｜三轴结局与编年史

**负责人建议**：Cursor 结局流程，Codex 验证，GPT 复核。

- 世界/玩家事业/角色尾声三轴组合；每一个世界级结局硬性前提可靠判定；第二轴可承载自由玩法。
- 编年史从真实事件提取，AI 只写标题/叙述，重要历史经过程序验证。
- 制作结局“本局获得/本局达成/账号总进度”、分享/导出（脱敏）和终局仪式微交互。

**验收**：同局重放/seed 决定性规则一致、不同玩家有不同个人尾声；不制造凭空英雄事迹；结局图文与拥有的钟心数/人物状态一致。

## 阶段 6｜世界各地区扩展与生产验收

**负责人建议**：WorkBuddy 视觉，Cursor 内容适配，Codex 性能安全。

- 将灰港切片的四层模型扩展到其他 7 个地区；批量迁移 436 段文本时按需审查状态前提。
- 173 张规划插图中未制作部分按实际剧情触发/影响优先制作；现有 12 样张可先用于风格检查，不把样张当正式完成资产。
- 完整端到端成本核算（AI 请求、结局强模型）、移动端/桌面体验、多房间联机、数据隐私、异常回退测试。

**验收**：真实 4 人试玩、长时间运行、网络抖动、旧存档版本提示、无障碍测试；记录未覆盖的自由意图与生成文本缺口；明确哪些故事内容不再需要硬编码。

## 严格完成定义（DoD）

- 需求有明确输入/输出、权威状态位置和失败回退。
- 新规则有单元测试；UI 有桌面/手机/键盘/屏幕阅读器路径；联机相关逻辑有并发/重连检查。
- 新剧情正文经事实前提验证；不强迫玩家进入预设事件。
- 每次变更更新当天 `修改日志/YY-MM-DD.md`，按项目规范完成 12 条复核；不能用“模型说做完了”代替实际检查。
- 没有用户新授权，不合并 PR、不部署、不付费、不删除旧数据。

## 建议的时间管理

先完成**规范 + 事件引擎 + 灰港垂直切片**，再批量扩展内容。不要把 UI、50 成就、全部 QTE、世界重写一次性塞进一个 PR；按 1–3 天可验收的小任务拆分更容易与多模型并行协作，具体时间以实际团队和资源为准，而不是承诺完成日。
